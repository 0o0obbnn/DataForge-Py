## 2. 产品概述

### 2.1 产品愿景

为软件开发与测试团队提供可视化、可交互的界面，以配置、生成、管理和交付高质量的测试数据，成为数据准备环节中不可或缺的效率平台，与强大的DataForge CLI引擎形成互补，让测试数据准备变得简单、高效、可靠。

### 2.2 产品目标 (SMART原则)

- **战略目标 (6个月)**：成为企业内部测试数据生成的首选可视化工具，覆盖70%以上的核心测试与开发团队
    
- **执行目标 (上线后3个月)**：
    
    - **用户增长**：每周活跃用户(WAU)达到200人
        
    - **效率提升**：用户通过界面生成数据的平均任务配置时间比CLI手动编写配置文件降低50%以上
        
    - **功能覆盖**：支持后端核心数据类型与生成规则的100%前端可视化配置
        

### 2.3 目标用户画像

#### 2.3.1 测试工程师（核心用户）

- **痛点**：
    
    - 手动造数据枯燥、易出错
        
    - 难以覆盖复杂场景和边界条件
        
    - 编写YAML/JSON配置文件的学习曲线陡峭
        
- **需求**：需要快速准备各种边界案例、大规模、符合业务逻辑的测试数据
    
- **典型场景**：在测试用户注册功能前，快速生成1000条包含中英文姓名、手机号、邮箱且逻辑自洽的测试数据，并导出为CSV文件
    

#### 2.3.2 开发人员

- **痛点**：在开发阶段希望快速mock数据，不想在测试数据准备上花费过多时间
    
- **需求**：需要快速生成特定格式的JSON数据，用于单元测试或接口调试
    
- **典型场景**：开发API时，需要快速生成一批结构复杂的请求体JSON数据，直接复制到测试代码中
    

#### 2.3.3 DevOps / 平台工程师

- **痛点**：需要将数据生成任务编排进CI/CD流水线，但缺乏直观方式来管理和审核配置
    
- **需求**：需要通过API方式集成数据生成能力，并确保配置的可靠性和一致性
    
- **典型场景**：在自动化部署完成后，通过调用Web控制台的API，触发预定义的数据初始化任务，为新环境注入基础数据
    

### 2.4 价值主张

**"化繁为简，一键生成"**：通过直观的Web界面，彻底降低使用强大DataForge引擎的学习和操作成本。用户无需记忆复杂的CLI参数与语法，即可通过点选、拖拽和简单配置，轻松生成任何所需的测试数据，极大提升测试数据准备的效率、准确性与体验。

## 3. 功能需求

### 3.1 功能列表与优先级

#### 3.1.1 Must-have (MVP核心功能)

- **配置管理**：创建、保存、加载、复制、删除数据生成配置
    
- **数据模板编排器**：可视化定义数据结构（对象、数组、嵌套）
    
- **动态字段配置**：基于元数据API，渲染核心数据类型的配置表单
    
- **实时数据预览**：生成并分页预览最多5条样本数据
    
- **结果下载**：将生成的数据以JSON/CSV格式下载到本地
    
- **核心数据类型支持**：string, integer, decimal, boolean, name, phone, email, date, timestamp, uuid
    
- **表达式编辑器**：用于配置复杂关联规则的高级代码模式
    

#### 3.1.2 Should-have (v1.1版本)

- **异步任务管理**：提交、查看、管理大规模生成任务
    
- **扩展数据类型支持**：id_card, address, url, ipv4
    
- **任务历史记录**：查看历次生成任务的配置和结果
    
- **批量操作**：支持批量生成、批量下载
    

#### 3.1.3 Could-have (v1.x后续版本)

- **可视化规则构建器**：通过UI配置关联规则的初级模式
    
- **团队与权限管理(RBAC)**：用户管理、配置的团队共享与权限控制
    
- **API集成**：提供RESTful API供外部系统调用
    
- **数据源管理**：支持外部数据源接入和管理
    
- **模板市场**：提供预置模板和用户共享模板
    

#### 3.1.4 Won't-have (本期不考虑)

- 所有安全注入类数据类型
    
- 媒体文件头等专业二进制类型
    
- 多租户SaaS化功能
    

### 3.2 用户故事

#### 3.2.1 US1: 快速生成基础测试数据

- **角色**：测试工程师
    
- **需求**：希望通过清晰的界面，选择几个常见字段（如姓名、手机号、日期），快速生成10条数据并下载，以便立即开始测试，而无需编写任何配置代码
    
- **验收标准**：
    
    - 用户可在3分钟内完成数据生成并下载
        
    - 生成的数据格式正确且符合预期
        
    - 界面操作不超过5步
        

#### 3.2.2 US2: 构建复杂嵌套数据

- **角色**：开发工程师
    
- **需求**：希望通过拖拽的方式，构建一个包含用户信息（对象）和订单列表（数组）的复杂JSON结构，并能为每个字段单独配置生成规则，以便生成用于测试订单查询API的精准数据
    
- **验收标准**：
    
    - 支持至少3层嵌套结构
        
    - 数组类型支持配置元素数量范围
        
    - 实时预览生成的数据结构
        

#### 3.2.3 US3: 配置高级业务规则

- **角色**：资深测试工程师
    
- **需求**：希望在配置数据时，能编写简单的表达式规则，确保生成的数据符合业务逻辑（例如："如果城市是北京，则手机号前缀只能是139或188"），以便模拟出更真实、有效的测试场景
    
- **验收标准**：
    
    - 表达式编辑器支持语法高亮和智能提示
        
    - 表达式语法简单易用，学习成本低
        
    - 规则验证失败时有明确错误提示
        

#### 3.2.4 US4: 集成到CI/CD流程

- **角色**：DevOps工程师
    
- **需求**：希望能够通过API密钥和curl命令，触发一个预先在Web界面上配置好的数据生成任务，并将生成的数据文件上传到指定位置，以便在自动化部署流程中完成数据初始化
    
- **验收标准**：
    
    - API接口稳定，响应时间<500ms
        
    - 支持身份认证和权限控制
        
    - 提供完整的API文档和示例
        

### 3.3 详细功能描述

#### 3.3.1 数据模板可视化编排器

- **功能描述**：核心界面采用三栏布局设计
    
    - **左栏**：组件库（可拖拽的字段类型、对象、数组）
        
    - **中栏**：画布区，以树形结构展示已配置的数据结构，支持拖拽排序、右键添加/删除字段
        
    - **右栏**：动态属性配置面板
        
- **业务规则**：
    
    - 根节点必须是一个对象或数组
        
    - 字段名需进行合法性校验（符合JSON/CSV命名规范）
        
    - 支持嵌套深度最大5层
        
- **交互细节**：
    
    - 用户可从左栏将"字段"拖入画布，或在树节点上右键选择"添加子字段"
        
    - 画布实时渲染缩略的JSON结构预览
        
    - 支持键盘快捷键操作（复制、粘贴、删除）
        

#### 3.3.2 字段级动态配置面板

- **功能描述**：当用户在画布中选择字段后，右栏面板动态切换为该字段的详细配置项
    
- **实现机制**：
    
    1. 前端调用后端 `GET /api/v1/metadata/generators` 接口获取数据生成器的元数据
        
    2. 元数据包含参数列表、UI类型、默认值、可选值等
        
    3. 前端根据元数据动态渲染相应的表单控件
        
- **配置示例**（姓名字段）：
    
    - "姓名类型"下拉框（中文/英文/混合）
        
    - "性别"下拉框（男/女/任意）
        
    - "自定义姓氏库文件路径"输入框
        
- **验证规则**：
    
    - 实时表单验证，错误信息即时显示
        
    - 支持必填项验证和格式验证
        

#### 3.3.3 表达式编辑器

- **功能描述**：为满足复杂关联规则配置，在字段配置中提供"高级模式"开关，开启后提供基于Monaco Editor的代码编辑器
    
- **核心能力**：
    
    - 语法高亮：支持JavaScript语法高亮
        
    - 智能提示：基于当前配置的字段名提供自动完成
        
    - 示例模板：提供常见场景的表达式示例
        
    - 语法检查：实时检查语法错误
        
- **安全机制**：所有表达式在后端受限的沙箱环境中执行
    
- **性能优化**：支持代码折叠、自动格式化等功能
    

#### 3.3.4 实时数据预览

- **功能描述**：在配置过程中提供实时预览功能，用户可查看生成的数据样本
    
- **实现机制**：
    
    - 用户点击"生成预览"按钮后，前端将当前配置发送给后端
        
    - 后端返回5条样本数据
        
    - 前端以表格和JSON两种格式展示数据
        
- **性能要求**：预览响应时间<2秒
    
- **交互细节**：
    
    - 支持分页查看多条数据
        
    - 支持展开/折叠JSON结构
        
    - 错误信息清晰显示

  ]
}

### 7.3 监控体系

- **前端监控**：Sentry for error tracking
    
- **性能监控**：Web Vitals + Custom Metrics
    
- **业务监控**：Custom Events + Analytics
    
- **基础设施**：Prometheus + Grafana
    

## 8. 附录

### 8.1 术语表

- **Data Schema**：数据模式，定义生成数据的结构
    
- **Generator**：数据生成器，负责生成特定类型的数据
    
- **Configuration**：生成配置，包含数据模式和生成参数
    
- **Task**：生成任务，一次具体的生成执行实例
    

### 8.2 开放问题

1. 表达式编辑器的语法规范细节需要与后端进一步确定
    
2. 脱敏策略的具体规则（如不同数据类型如何脱敏）需要详细定义
    
3. 大规模数据生成时的内存管理和优化策略
    
4. 国际化和多语言支持的具体范围和时间安排
    

### 8.3 风险评估与缓解措施

- **技术风险**：动态表单渲染性能问题
    
    - **缓解**：采用虚拟滚动、分页加载、组件懒加载
        
- **安全风险**：表达式执行安全漏洞
    
    - **缓解**：严格的沙箱环境、输入验证、安全审计
        
- **资源风险**：大规模生成时的资源消耗
    
    - **缓解**：资源限制、队列管理、自动扩缩容
