# 硬编码数据配置化迁移计划

## 计划概述

本计划详细描述了将 DataForge 项目中硬编码数据迁移到配置文件的完整实施方案，包括时间表、实施步骤、测试策略和风险控制。

**制定日期**: 2025-12-22
**预计开始**: 2025-12-23
**预计完成**: 2025-12-30（7个工作日）

## 实施优先级

### 阶段一：高优先级生成器（预计 4 个工作日）

1. **occupation.py** - 职业/职位生成器（2 天）
   - 数据量最大（500+ 行）
   - 业务价值高
   - 复杂度：高

2. **education.py** - 教育水平生成器（1.5 天）
   - 数据量较大（200+ 行）
   - 经常需要更新学校列表
   - 复杂度：中

3. **license_plate.py** - 车牌号生成器（0.5 天）
   - 数据量中等（40 行）
   - 相对稳定
   - 复杂度：低

### 阶段二：优化和统一（预计 2 个工作日）

4. **context_aware.py** - 上下文感知生成器（1 天）
   - 数据量小（60 行）
   - 需要统一到现有数据文件
   - 复杂度：低

5. **address.py** - 地址生成器优化（1 天）
   - 已有数据加载器
   - 需要优化 fallback 机制
   - 复杂度：低

### 阶段三：测试和文档（预计 1 个工作日）

6. **集成测试和文档**（1 天）
   - 端到端测试
   - 性能测试
   - 文档更新

### 任务 1.1：occupation.py 配置化

**预计时间**: 2 个工作日
**负责人**: 开发团队
**依赖**: 无

#### 实施步骤

**步骤 1.1.1：创建配置文件（0.5 天）**
- [ ] 创建 `resources/occupation_zh.yaml`
  - 结构设计：
    ```yaml
    occupation:
      industries:
        IT:
          name: "IT/互联网"
          positions:
            SENIOR: [...]
            MIDDLE: [...]
            JUNIOR: [...]
            INTERN: [...]
          departments: [...]
        # ... 其他行业
      generic_positions:
        SENIOR: [...]
        MIDDLE: [...]
        JUNIOR: [...]
        INTERN: [...]
      translations:
        # 中文到英文的翻译映射
    ```
- [ ] 创建 `resources/occupation_en.yaml`（可选，用于英文职位）
- [ ] 验证 YAML 格式正确性

**步骤 1.1.2：创建配置加载器（0.5 天）**
- [ ] 创建 `resources/occupation_loader.py`
  - 参考 `company_name_loader.py` 的实现模式
  - 实现 `load_occupation_config(locale="zh_CN")` 函数
  - 使用 `@lru_cache` 实现缓存
  - 实现 fallback 机制（使用硬编码默认值）
  - 添加错误处理和日志记录

**步骤 1.1.3：修改生成器（0.5 天）**
- [ ] 修改 `generators/basic/occupation.py`
  - 在 `_setup()` 中调用 `load_occupation_config()`
  - 移除硬编码的 `self.industries`、`self.generic_positions`、`self.departments`
  - 保留 `_to_english()` 方法，但从配置加载翻译映射
  - 更新 `supported_parameters` 添加 `locale` 参数
  - 保持向后兼容性

**步骤 1.1.4：补充测试用例（0.5 天）**
- [ ] 检查现有测试：`tests/unit/test_generators/test_basic/test_occupation.py`

- [ ] 添加不同行业参数测试
- [ ] 添加不同级别参数测试
- [ ] 添加 locale 参数测试
- [ ] 添加配置缓存测试
- [ ] 添加 fallback 机制测试（模拟配置文件缺失）

### 风险识别

| 风险 | 影响 | 概率 | 缓解措施 |
